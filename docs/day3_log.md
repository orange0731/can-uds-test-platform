## 学到的知识点
- 切回默认会话必须重置安全锁（防权限残留漏洞）
- NRC 的返回顺序取决于 ECU 实现和具体服务。ISO 14229-1 给出了服务器处理请求的推荐顺序，但不同 ECU 厂商可能有细微差异。典型顺序更接近：
服务支持(0x11) → 子功能支持(0x12) → 会话支持(0x7F/0x7E) 
→ 安全访问(0x33) → 消息长度(0x13) → 请求范围(0x31) → 条件(0x22) → 序列(0x24) ...
长度检查（0x13）的位置比较特殊：有些 ECU 会先检查长度，因为长度不对就无法解析子功能；但更多实现是在服务/子功能支持之后检查长度。所以把 0x13 放在最前面不是通用规则
- 写后回读是验证"写入真正生效"的必要手段
写后回读（Write → ReadDataByIdentifier）确实是验证写入是否真正生效的最常用、最推荐的手段。因为 ECU 返回肯定响应（0x6E）只代表请求被接收并处理，不代表数据已持久化或实际生效。回读可以确认当前值已改变。
但说“必要手段”过于绝对：
有些场景可以通过复位后重新读取来验证持久化；有些 ECU 提供状态位、校验和或专用例程（0x31）来确认；如果测试目标只是验证协议交互，回读并非必须。更准确的表述是：写后回读是验证写入生效的推荐且通常必要的手段，但不是唯一手段。
